# Gmail の特定の件名のメールに自動返信する

件名に決まった言葉（例:「お問い合わせ」「【申込】」）を含むメールが届いたら、
用意した文面で自動的に返信します。GitHub Actions が10分ごとに Gmail を見に行くので、
PC を開いていなくても動きます。

```
届いたメール: 件名「お問い合わせ: 料金について」 From: 山田 太郎
        ↓ 10分以内
自動で返信: 件名「Re: お問い合わせ: 料金について」（同じスレッドに入る）
        山田 太郎 様
        お問い合わせいただきありがとうございます。…
```

## しくみ

| やること | 方法 | 理由 |
|---|---|---|
| メールを読む | IMAP（アプリパスワード） | Google Cloud や OAuth の設定が要らない |
| 返信する | SMTP（同じアプリパスワード） | ブリーフィングのメール通知と同じ設定を使い回せる |
| 二度返信しない | 返信したメールに Gmail のラベル `auto-replied` を付ける | Gmail の画面でも返信済みがひと目でわかる |
| 定期実行 | GitHub Actions（10分ごと） | サーバー不要。公開リポジトリなので無料 |

### 返信しないメール（暴走よけ）

- 自分から届いたメール
- `noreply` / `mailer-daemon` など送信専用アドレス
- 相手の自動返信、メルマガ、メーリングリスト
- 1回の実行で、同じ相手には1通だけ
- 1回の実行で返信するのは `max_per_run` 通まで（残りは次回）

フォームの通知メールのように **From が送信専用でも Reply-To にお客さんのアドレスがある**場合は、
Reply-To 宛てに返信します。

## セットアップ

### 1. Gmail 側の準備（5分）

1. **IMAP を有効にする**: Gmail →「設定」→「すべての設定を表示」→「メール転送と POP/IMAP」→
   「IMAP を有効にする」→ 保存
2. **アプリパスワード**: すでにブリーフィングのメール通知用に作っていればそれを使います。
   まだなら Google アカウント →「セキュリティ」→ 2段階認証を有効にしたうえで
   「アプリパスワード」を作成（16文字）

### 2. 件名と返信文を決める

`config.yaml` の `autoreply` を編集します。

```yaml
autoreply:
  enabled: false        # 確認が済むまで false のまま
  from_name: "三沢"
  mode: send            # 心配なら最初は draft（下書きに入るだけ）
  rules:
    - name: お問い合わせ
      subject_contains: ["お問い合わせ"]
      body: |
        {name} 様

        お問い合わせいただきありがとうございます。
        内容を確認のうえ、2営業日以内にご連絡いたします。
```

- `subject_contains` は**どれか1つを含めば**対象。全角/半角・大文字/小文字・空白の違いは無視します
- 細かく指定したいときは `subject_regex`（正規表現）。例: `"^【申込】"` で「件名の先頭が【申込】」
- ルールは複数書けます。上から順に見て、最初に合ったものを使います
- 返信文に差し込める項目: `{name}` 相手の名前 / `{email}` 相手のアドレス / `{subject}` 元の件名 / `{date}` 受信日時

> ⚠️ このリポジトリは**公開**です。`config.yaml` に書いた件名や返信文は誰でも読めます。
> 定型のお礼文なら問題ありませんが、人に見せたくない内容は書かないでください。

### 3. 手元で確認する（送信はしない）

```bash
set -a; source .env; set +a          # SMTP_USERNAME と SMTP_PASSWORD を読み込む
python -m secretary autoreply --dry-run
```

```
  ✓ 返信予定: [お問い合わせ] 山田 太郎 <taro@example.com> 「お問い合わせ: 料金について」
    件名: Re: お問い合わせ: 料金について
    山田 太郎 様
    ...
  - 返信しない: [お問い合わせ] <noreply@example.com> 「お問い合わせを受け付けました」（送信専用アドレス）
返信予定 1件 / 対象外 1件 / 失敗 0件
（--dry-run なので送っていません）
```

**ここに出た相手に、この文面が送られます。** 想定外の相手が混ざっていないか確認してください。

### 4. 自動で動かす

1. GitHub のリポジトリ →「Settings」→「Secrets and variables」→「Actions」に
   `SMTP_USERNAME`（Gmailアドレス）と `SMTP_PASSWORD`（アプリパスワード）があることを確認
2. `config.yaml` の `autoreply.enabled` を `true` にしてコミット
3. 「Actions」タブ →「メール自動返信」→「Run workflow」で `dry_run` にチェックを入れて1回試す
4. 問題なければ、あとは10分ごとに自動で動きます

Actions のログは公開されるため、相手のアドレスは `t***@example.com` のように伏せ、
件名や本文は出しません。

## 注意点

- **有効にした直後**は、過去 `lookback_days` 日（既定1日）に届いた該当メールにも返信します。
  古いメールに返したくなければ、先にそれらへ Gmail で `auto-replied` ラベルを付けておいてください
- GitHub Actions の定期実行は混雑で**数分〜十数分遅れる**ことがあります。即時の返信が必要なら、
  Gmail 標準の「テンプレート＋フィルタ」（下記）のほうが確実です
- 返信に失敗したメールはラベルを外すので、次回もう一度試します
- 止めたいときは `enabled: false` にするか、Actions タブでワークフローを「Disable」

### 参考: コードを使わない方法（Gmail 標準機能）

固定の文面で即時に返せればよいだけなら、Gmail の機能だけでもできます。

1. 設定 →「詳細」→「テンプレート」を有効化
2. 新規作成で返信文を書き、︙ →「テンプレート」→「下書きをテンプレートとして保存」
3. 検索ボックスで `subject:(お問い合わせ)` → フィルタを作成 →「テンプレートを送信」

ただしこの方法では、相手の名前を差し込めません。Reply-To 宛てにも返せず、
noreply や自動返信を除外することもできません。このリポジトリの仕組みは、その3つを補うためのものです。
